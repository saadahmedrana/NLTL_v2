# Implemented checks and limits

The deterministic checker uses exact locked identifiers (including custom explicitly declared units), property kinds, supported datatype IRIs, explicit object/literal constraints, canonical quantity units and complete explicit model paths. An identifier namespace substitution can be suggested when the local identifier uniquely matches a locked term. Scale/unit changes require source-backed conversion; the checker does not edit numeric values. RDF 1.1 plain strings are already xsd:string; no generic string/number coercion is applied.

Turtle and all embedded sh:select queries are parsed. Flat BGP/BIND/FILTER analysis detects supported unbound operands, missing $this projection, simple operand/path/unit errors. Complex OPTIONAL/UNION/EXISTS/subquery algebra, inverse/alternative/repeated paths, arbitrary functions, dynamic predicates and general SPARQL type inference are not proven by this checker. Structural property paths and nested sh:node/and/or/xone/not are traversed where supported. Unsupported ownership or target binding remains unresolved; no broad-domain owner assumption is made. Runtime execution on approved synthetic targets catches execution failures separately from conformance, but cannot exercise every branch.

The evidence-bound reviewer validates its JSON structure, source clause/excerpts, candidate excerpts and schema evidence. It does not mechanically prove a model's regulatory interpretation. Explicit conflicting proposed paths stop the loop. Unsupported reviewer claims cannot authorize a contract change. Format failures/truncation retain raw output and finish reasons and are not regulatory rejections. Reviewer retries/token limits are configurable. There are no unbounded provider retries or fresh regeneration.

The repair guard records diffs and resolved/persistent/new findings. It flags removed paths, constraints, threshold/value, target, logical operator and query changes. Only narrowly evidenced corrections may discharge a matching change. This is conservative; legitimate complex rewrites may need adjudication. It is not a complete semantic equivalence proof. Findings from all applicable checks are recomputed after each code revision; disappearance alone cannot establish repair success.

Independent evaluation's automatic strict attribution currently recognizes exact pre-reviewed source-authored query bodies in the six-requirement core. Ordinary verdicts work for arbitrary executable submitted shapes. Other query/wrapper meanings require additional evidence-backed semantic specifications and otherwise remain UNRESOLVED_ATTRIBUTION. No negative receives strict credit merely because it rejects and its counterpart passes. The original-no-verdict flag takes precedence.

Schema audit: R13 parses as 24,100 triples with no undefined internal NLTL references. Six registry entries have no explicit OWL property-kind declaration: classificationSocietyScantling, lowerIceWaterline, propellerType, regulationDerivedScantling, steelGrade, upperIceWaterline. Their string ranges are present; missing declarations are review gaps, not proof of wrong ownership. Custom NLTL unit IRIs are explicitly declared qudt:Unit and are valid locked identifiers. There are 840 requirement/property occurrences without explicit termOwners bindings across the full index, including legacy terms; these are not 840 confirmed defects. No explicit disjoint-class contradiction was found by the supported scan. A complete ontology consistency/contract review has not been established.

Missing study inputs: reviewed coverage/certified fixtures and intended-only repairs for 44 additional requirements; reviewed attribution specifications beyond the narrow core recognizer; a live endpoint/model compatibility test (intentionally not run); real generation histories and token/runtime measurements. The data registry contains 313 source requirements, not a newly certified 313-requirement benchmark. Non-core fixtures are deliberately not bundled and retain their individual blockers/statuses. Historical classifications are inert snapshots with provenance links, not runtime data dependencies.

Known source context blocker: TRF-002's frozen text omits the earlier-date exception in the full source section 1.2. The exact source excerpt and hash are bundled in data/contracts/context_issues.json and supplied as unresolved context. NLTL will not turn this omission into a confirmed code defect or continue repairs past it. The original requirement text is preserved.
