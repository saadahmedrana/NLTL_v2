Frozen TRF-035 reviewer-only comparison launcher — READY, NOT DISPATCHED

This launcher is an experiment-local script, not a production pipeline change or new framework. It uses the existing HostedResponsesTransport, core review validation and source/schema state. The shared comparison-only coverage field is validated separately; raw outputs and explicit review projections are both preserved without altering substantive claims. No response earns production approval/repair authority.

Only TRF-035, two reviewer arms. No additional requirements, generation, candidate edits, repair or retrieval. A uses the frozen current prompt; B the already prepared generic coverage prompt. No prompt improvements or per-requirement changes were made to prepare the launcher. All original comparison.freeze.json artifacts and all 87 frozen production/resource hashes verify unchanged.

At most two primary reviews and one shared correction per arm: FOUR physical calls, 16,000 output tokens/request, 64,000 output reservation, 180-second request timeout, 600-second dispatch window. A valid review finishes its arm. An ordinary response-protocol failure exhausts only that arm's existing correction then proceeds to the next arm. Infrastructure/integrity failure stops the experiment, preserving the started arm's error and marking only unstarted arms NOT_RUN. Existing run IDs cannot be reused; no rerun loop, fallback or changing criteria.

--preflight is offline and blocks network. It verifies original comparison files, exact candidate/evidence bindings, production identity, input/output capacity and external credential presence without printing credentials. Provider framing/lower limits remain unexposed; no truncation. Execution requires BOTH --allow-model-calls and NLTL_ALLOW_MODEL_CALLS=YES.

Progress is printed immediately at every arm/request/correction/closure transition, e.g. done=1/2 in_progress=1 pending=0 calls=2/4. There is one request in flight at most. Inspect output/progress.json while a call is waiting; progress counts arms, not requirements. Input/response/provider usage/latency and validation artifacts are saved under outputs/experiments/20261125_V0115_TRF035_FROZEN_REVIEW_COMPARISON_01/. The final dispatch_closed.json preserves all arm outcomes and NOT_RUN entries. No evaluation is triggered.

Offline checks: generic reference/location/coverage forms, unchanged review-field projection, truncation, failure classes and 4-call bound pass. Scripted loop controls pass for both arms validating (2 fake dispatches), both arms exhausting correction (4 fake dispatches), and infrastructure stopping after the first attempt (1 fake dispatch; B NOT_RUN). All are software-only evidence, zero actual model calls, no accuracy credit.

classification_policy.json separates transport/infrastructure, pipeline integrity/routing/missing IO, reviewer protocol failure, substantive interpretation/code error, genuine source/schema ambiguity and evaluation/attribution uncertainty. Validity is not correctness, model questions are not automatically genuine ambiguity, and an invalid review is not automatically a software bug. Raw evidence is retained. After closure, substantive classification and coverage completeness require independent source/code inspection; compare general patterns with earlier saved requirements without expanding this launch.
